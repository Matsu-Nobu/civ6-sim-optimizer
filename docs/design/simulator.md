# シミュレータ設計（草案 v0）

## ルールの入手元

ゲームは最後に読み込んだルール（BBGなどのmod適用後）を
`%LOCALAPPDATA%/Firaxis Games/Sid Meier's Civilization VI/Cache/DebugGameplay.sqlite` に書き出す。
SQLを自前で解釈する必要はなく、このDBをそのまま読めばよい。

- コピー: data/rules/gameplay_2026-10-04.sqlite（BBG 7.5.1 のゲーム後。BBGのModifierが1699件）
- BBGが更新されたら、新しい版で1回ゲームを読み込んでDBをコピーし直すだけ
- コストは標準速度の値。ゲーム速度の倍率は GameSpeeds テーブルから掛ける（オンライン速度など）
- 成長: GlobalParameters の CITY_GROWTH_THRESHOLD=15, MULTIPLIER=8, EXPONENT=1.5, 1人あたり食料消費=2

## 対象範囲（v0）

- 1文明、T1〜T60程度、戦闘・外交・宗教なし
- マップの幾何は持たない。都市ごとにタイル在庫（種類×枚数）を持つ。2/2タイルがベースライン
- 開拓者から都市建設までのターン数、新都市のタイル在庫などはYAMLのパラメータ

## 状態

帝国
- turn, gold, faith
- 科学: 完了した技術、各技術の進捗、ブースト済み、研究中
- 文化: 完了した社会制度、進捗、インスピレーション済み、研究中
- 政体、セットしている政策
- ユニット: 労働者（残りチャージ）、移動中の開拓者（到着ターン）、交易商

都市
- 人口、食料の蓄積
- 生産中のもの、各品目の生産の蓄積（Civ6は切り替えても蓄積が残る）
- 建造物、区域
- タイル在庫と、その改善状態（未改善・改善済み・伐採済み）

## 行動（判断点でだけ選ぶ）

- 都市の生産が完了したとき: 次に作るもの
- 研究/社会制度が完了したとき: 次の研究
- 社会制度の完了時: 政策の付け替え、政体の変更
- ゴールドが購入可能額に達したとき: 購入するか
- 労働者が使えるとき: どのタイルを改善するか／伐採するか
- 市民の配置は探索せず、目的に応じた貪欲法で自動決定

## 1ターンの処理順

ゲームの実際の順序に合わせる（要確認）:
産出の計算 → 生産・研究・文化に加算 → 完成判定（あふれた分は持ち越し） → 食料の加算と成長判定 → ゴールド

## セーブとの対応

| シミュレータの状態 | セーブの項目 | 状況 |
|---|---|---|
| 技術・社会制度・進捗 | techsResearched / techProgress / civicProgress など | 読める |
| 政体・政策 | government / policiesSlotted | 読める |
| ゴールド | gold / goldPerTurn | 読める |
| 人口・働かせているタイル | city.population / workedPlots | 読める |
| 生産中と蓄積 | city.production.current / progress | 読める |
| 食料の蓄積 | city.food | 壊れている（全都市 38517.5） |
| 労働者のチャージ | units（builder charges） | 読める |
| 毎ターンの産出 | player.yields | 読める → シミュレータの計算結果と照合に使う |

## 精度確認の方法

セーブ T のプレイヤーの状態と、T→T+1 で実際に取った行動をシミュレータに与え、
T+1 の産出・ゴールド・生産の蓄積が実セーブと一致するかを見る。

## 時間発展: 生産の蓄積（2026-10-05）

python_legacy/scripts/check_production.py で T→T+1 の生産の蓄積を照合（33ターン一致、3ターン差）
- 毎ターンの増分 = その状態の生産量 ×（1 + 快適性の% + 品目別の%）
- 完成時のあふれは、セーブ上は次の品目に0と記録され、翌ターンに次の品目へ加算される
- 途中で別の品目に切り替えた場合、元の品目の蓄積は残る（クマエ T26 開拓者 23 → T30 に再開）
- コスト = floor(基本コスト × ゲーム速度倍率)。開拓者は +30/体、労働者は +4/体（COST_PROGRESSION_PREVIOUS_COPIES）
- 総督・修飾子は OwnerRequirementSet（指導者条件など）を評価する。梁のギルドマスター+15% はマリア・テレジア専用だった
- 未実装: 交易商（ゲームの進行度で変動、実測21）と区域（COST_PROGRESSION_NUM_UNDER_AVG_PLUS_TECH、政府区域の実測≈24.2）のコスト、
  快適性（幸福 +8%）の計算、伐採による生産（クマエ T15 の +5 はおそらく伐採）

## 時間発展シミュレータ（civ6sim/sim.py）と通しの再現（python_legacy/scripts/replay.py）

T2 の状態から、蓄積（生産・あふれ・食料・人口・研究・社会制度・ゴールド）をシミュレータだけで進め、
プレイヤーの選択（生産品目・研究・タイル・政策・ブースト）はセーブから与える。T3〜T23 は全項目一致。
確定した規則:
- 研究/社会制度のコスト = floor(基本×0.5×時代補正)。ゲームの時代より後の時代は 技術+30% / 社会制度+20%
- ブースト = floor(0.4×(コスト−2.5))（9件で一致、理由不明）。Boosts に行がない項目（法典・畜産）はフラグだけで進捗なし
- 成長に必要な食料 = floor((15 + 8(n−1) + (n−1)^1.5) × 0.5)。あふれは持ち越し
- 住宅: 川5 + 建物 + 改善(Housing/TilesRequired)。残り1以下で50%、0以下で25%、−4以下で0%
- 快適性 = 改善済み贅沢資源の種類（1枚につき最大4都市）+ 無料1 + 宮殿1 − ceil(人口/2)。3〜4で「幸福」: 食料以外+8%・成長+8%
- 開拓者完成ターンは、人口−1してから食料を計算（最も食料の少ないタイルの市民が外れる）
- 生産品目が未選択のターン（建設直後など）の生産は保留され、次の品目に加算
- 文化の人口あたり0.3は 1/256 単位で切り捨て（76/256）
- 区域コスト: 政府区域 25（基本30）→ 基本×5/6 を暫定採用。交易商 21（暫定固定値）
- 食料の蓄積はパーサーが読めないため、`LOC_CITY_NAME_<都市>` の後の `0,0,23` の次の値（×256）から読む
未対応: 社会制度完了で同じターンに無料建造物が入る順序（クマエ T23→24 の穀物庫）、ローマ T28〜 の食料+1〜2

## Econ Probe で確定した規則（2026-10-06, スキタイの試合 T18〜T21 と照合: python_legacy/scripts/check_probe.py）

- 購入価格（ゴールド）= floor5(4 × 生産コスト)。生産コストは 基本×速度 を先に切り捨て（投石兵 35→17→65G）。信仰はその半分
  例外: 交易商（ゲーム進行で端数が増え 80→85）、開拓者/労働者の購入は生産コストより1体分高いことがある（未解明）
- 研究/社会制度コスト = floor(floor(基本) × 0.5 × 時代補正)（BBGの端数つき基本値 409.5、社会制度 175×0.5×1.2=105 に一致）
- 国境: 文化の累計（あふれ持ち越し）、コスト floor(0.5 × (10 + (6n)^1.3))、n は文化で得たタイル数（購入は数えず、文化も消費しない）
- 快適性: 必要数 = ceil(人口/2) − 1、供給 = 贅沢資源 + 宮殿（「無料1」ではなく必要数側で引く）
- 住宅はゲーム表示では切り捨て（7.5→7）
- 戦略資源の産出は公開技術の後から（鉄は青銅器）
- 区域のあるタイル（建設中を含む）はタイル自体の産出なし
- 改善の隣接ボーナス（Improvement_Adjacencies）: クルガンは隣接する牧草地ごとに生産+1・信仰+1
- 不満（快適性 −1〜−3）: 食料以外 −10%
- パーサーが名前を知らない資源（BBM のメープル等）は、ハッシュをルールDBの名前で引く（export_game.sh が RESOURCES を渡す）
未解明: 区域コスト（野営地 ゲーム34 / 式36、購入140）、交易商コストの進行度の定義
- 区域コスト（2026-10-06）: BBG base.sql が CostProgressionParam1 を 35（政府区域・外交街区 20）に変更 = 割引率。
  割引条件（コミュニティ解析）: A=解禁済みの特殊区域の種類数, B=完成済み特殊区域数, C=その種類の配置済み+完成数 で B>=A かつ B/A>C。
  上昇分: base×0.5×(1+K×max(技術割合, 社会制度割合))。コミュニティは K=9、観測3件は K=7.7〜8.5 → 暫定 K=8.1。
  「配置時にコスト固定」はローマの政府区域（完成時の値25でのみ一致）と合わないので無効（LOCK_DISTRICT_COST=False）
