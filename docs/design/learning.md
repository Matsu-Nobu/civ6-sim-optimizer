# 概要

探索と学習を交互に回して、計画の探索を強くする。探索は、計画の決定を 1 つずつ変えて点数が上がる変更を残す。学習は、探索が遊んだ局面から、局面ごとにどの選択肢が強いか（方策）と、その局面から最後までに得る点数（価値）を予測するモデルを作る。学習したモデルは、次の探索で候補の順番づけと途中の評価に使う。

決定の種類ごとに場当たりの規則を作らず、すべての種類の決定を同じ仕組みで学習する。

# 背景

今の探索は、次の 2 つの理由で、明らかに良い計画の手前で止まる。

- 計画を「都市ごとの何回目の選択か」の並びで持つので、途中に品目を差し込むと、後の選択がすべてずれる。
- 浴場のように、先に損をして後で効く手は、1 つずつの変更では点数が上がらないので採用されない。

以前、局面の価値を 21 個の数の線形の式で学習したが（`optimizer/src/value.rs`）、条件で変わる関係を表せず、結果も安定しなかった。

# 段階

## 局面と選択肢のデータを集める

探索が遊ぶ計画の 1 回ごとに、決定の局面の特徴、選択肢ごとの特徴、選んだ選択肢、最後の点数を記録する。特徴は、すべての決定の種類で共通の項目（ターン、産出、人口、研究の進みなど）と、決定の種類ごとの項目（都市の住宅の残り、品目の費用や産出など）に分ける。

終える条件は、今日の対局（10/21 ローマ戦）の探索 1 回から、生産・労働者・研究の決定について数十万件の記録が取れること。

## 価値と方策のモデルを作る

Python の機械学習の道具がこの環境に無く、探索は Windows の Rust のプログラムで動くので、モデルは Rust で作る。モデルは、決定木を多数足し合わせる勾配ブースティングとする。価値は局面の特徴から最後の点数を予測する。方策は局面と選択肢の特徴から、その選択肢の点数を予測する。

終える条件は、学習に使っていない計画の局面で、価値の予測誤差と、方策が選ぶ選択肢と探索が選んだ選択肢の一致率を測り、何も学習しない場合（平均値、既定の規則）より良いこと。

## モデルを探索に組み込む

探索で決定を変えるとき、方策の予測が高い選択肢から試す。計画の後半を打つときは、決まった規則の代わりに方策を使う。

終える条件は、同じ計算時間で、今の探索の結果（13,928 点）を上回ること。

## 探索と学習を繰り返す

組み込んだ探索で新しいデータを集め、モデルを学び直し、また探索する。

終える条件は、繰り返しても点数が上がらなくなること。上がらなくなった点数が今の探索の結果を上回らなければ、この方針をやめ、探索の決定の持ち方と変え方を直す方針に戻る。
